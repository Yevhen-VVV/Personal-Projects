# Domain 5: Identity and Access Management (13% of the exam)

## D5-001 | 5.1 | 1
Q: An employee holds the door open so a stranger can follow them into a secure area without badging. Which physical control is designed to prevent this?
A)* An access control vestibule (mantrap)
= Correct. A vestibule lets only one authenticated person through at a time, stopping tailgating and piggybacking.
B) A badge reader with a longer read range
= Read range does not stop a second person walking through behind the first.
C) A security camera recording the door all day
= Cameras deter and record tailgating but do not physically prevent it.
D) A sign reminding staff not to hold the door for others
= Signs raise awareness but enforce nothing.
>> Tailgating and piggybacking are stopped by vestibules, turnstiles and guards, and reinforced by awareness.

## D5-002 | 5.1 | 2
Q: A company wants one place to control access to all its SaaS applications, so that disabling a user there removes their access to every app. What should it implement?
A)* A central identity provider with single sign-on for each application
= Correct. Centralizing authentication means access decisions and deprovisioning happen in one place for information, systems, applications and services.
B) Separate local accounts in each application, reviewed every quarter
= Local accounts multiply the places where a leaver keeps access.
C) A shared administrator password for each application stored in a vault
= Shared credentials remove individual accountability.
D) A network firewall rule blocking each departing user's IP address
= Users change IP addresses; network rules do not track identity.
>> Logical access control is strongest when identity is centralized and every application trusts it.

## D5-004 | 5.1 | 2

## D5-005 | 5.2 | 1
Q: A login requires a password and a security question answer. Why is this NOT multifactor authentication?
A) Security questions are never stored securely
= Storage is a separate issue; the factor type is the problem.
B) Two factors are needed, and this has three
= There are only two items here, and both are the same type.
C)* Both are something you know

## D5-006 | 5.2 | 2
Q: A biometric system's sensitivity is raised so that it rejects more impostors. What happens to its error rates?
A)* The false acceptance rate falls and the false rejection rate rises
= Correct. Stricter matching lets fewer impostors in (fewer Type II errors) but rejects more legitimate users (more Type I errors).
B) Both error rates fall together
= Sensitivity trades one error for the other; both cannot fall together.
C) The false rejection rate falls and the false acceptance rate rises
= That is what happens when sensitivity is lowered.
D) Neither rate changes, only the crossover error rate does
= The CER is a property of the device; adjusting sensitivity moves both FAR and FRR.
>> FRR = Type I (false rejection); FAR = Type II (false acceptance). The CER (EER) compares devices: lower is better.

## D5-007 | 5.2 | 2
Q: When comparing biometric devices, which measure indicates overall accuracy?
A) The false rejection rate alone
= FRR alone ignores impostor acceptance.
B) The time needed to enroll each user
= Enrollment time affects acceptability, not accuracy.
C) The throughput rate
= Throughput is how many people per minute can be processed.
D)* The crossover error rate (CER)
= Correct. The CER, also called the equal error rate, is where FAR equals FRR; a lower CER means a more accurate device.
>> Use the crossover error rate to compare biometric accuracy; a lower CER is better.

## D5-008 | 5.2 | 1
Q: In biometrics, what is a Type II error?
A) A legitimate user is rejected
= That is a Type I error, false rejection.
B)* An impostor is accepted
= Correct. False acceptance is the more dangerous error for security.
C) The sensor fails to capture a sample
= That is a failure to capture, not a Type II error.
D) A user cannot be enrolled
= That is a failure to enroll.
>> Type I = false rejection (annoying); Type II = false acceptance (dangerous).

## D5-009 | 5.2 | 2
Q: Users keep approving MFA push notifications they did not request after attackers bombard them with prompts. Which change MOST directly counters this?
A) Sending prompts by SMS instead of push
= SMS codes are phishable and can be intercepted by SIM swapping.
B) Shortening the push notification timeout
= A shorter timeout does not stop a user from approving the prompt.
C)* Number matching on the login screen
= Correct. The user must type a code shown on the actual login screen to approve, so blind approvals of unsolicited prompts fail.
D) Training users to approve only during working hours
= Attackers can time their attempts to working hours.
>> MFA fatigue (prompt bombing) is countered by number matching, rate limits and phishing-resistant authenticators.

## D5-010 | 5.2 | 2
Q: Which authentication method is MOST resistant to phishing?
A) One-time codes from an authenticator app
= Users can be tricked into typing the code into a fake site that relays it.
B) SMS one-time passcodes
= SMS codes can be phished, intercepted or redirected through SIM swapping.
C) Push notifications without number matching
= Push approvals can be relayed or approved out of fatigue.
D)* FIDO2 passkeys or security keys
= Correct. FIDO2 binds each credential to the real website's origin, so a look-alike site cannot use it.
>> Passwordless FIDO2/WebAuthn (passkeys, security keys) is phishing-resistant because credentials are bound to the origin.

## D5-011 | 5.2 | 2
Q: Following NIST SP 800-63B, which password practice should an organization adopt?
A) Force all users to change passwords every 60 days
= Routine forced changes lead to weaker, predictable passwords; change only on evidence of compromise.
B)* Check new passwords against lists of known breached passwords
= Correct. Screening against compromised and common passwords blocks the passwords attackers try first.
C) Require at least one uppercase letter, number and symbol
= Composition rules add little strength and frustrate users; length matters more.
D) Allow password hints visible to anyone at the login screen
= Hints help attackers guess.
>> NIST 800-63B: favor length, screen against breached lists, allow paste and password managers, no forced periodic changes, no hints.
