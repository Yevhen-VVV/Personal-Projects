# Domain 6: Security Assessment and Testing (12% of the exam)

## D6-001 | 6.1 | 2
Q: A company's customers want assurance about its security controls from someone other than the company's own staff. Which option gives them the MOST independent view?
A)* An audit by an outside audit firm
= Correct. External auditors are outside the organization's control and have no stake in the result, so customers and regulators can rely on their findings.
B) An internal audit by the company's own audit team
= Internal auditors can be independent of the areas they audit, but they are still the company's employees.
C) A self-assessment questionnaire completed by IT
= Self-assessment is the least independent option of all.
D) A review by the developers who built the system
= Builders reviewing their own work have an obvious conflict of interest.
>> Internal audits use the organization's own staff; external audits use an outside firm; third-party audits are performed by or for another organization, such as a customer or regulator.

## D6-002 | 6.1 | 2
Q: Before a penetration test begins, what MUST be in place?
A) A list of the vulnerabilities the testers are expected to find
= Testers discover vulnerabilities; they do not start with a list of expected findings.
B)* Written authorization and agreed rules of engagement
= Correct. Signed permission from someone with authority, plus scope, timing, methods and contacts, separates a test from an attack.
C) Full administrator credentials for every system
= Credentials depend on the test type; many tests start with none.
D) A press release announcing the test
= Tests are usually kept to a small group to avoid tipping off staff or attackers.
>> Never test without written authorization and rules of engagement that define scope, methods, timing and contacts.

## D6-003 | 6.1 | 2
Q: A company wants to penetration-test its application running on a major public cloud platform. What should it check FIRST?
A) Whether its own firewall allows outbound scans
= Outbound rules matter less than whether testing is permitted at all.
B) Whether the testers have cloud certifications
= Tester qualifications matter, but permission comes first.
C)* The provider's rules on customer testing
= Correct. The cloud provider's testing policy sets what customers may test, and testing their shared infrastructure without permission can breach the contract or the law.
D) Whether the test can be run during business hours
= Timing is part of planning, after confirming the test is permitted.
>> Location matters: on-premises, cloud and hybrid environments have different ownership, permissions and responsibilities for testing.

## D6-004 | 6.1 | 2
Q: How should an organization decide which systems to assess most often?
A) Alphabetically, so every system gets its turn
= An arbitrary order ignores risk.
B) By whichever system administrators volunteer
= Volunteering does not reflect risk.
C) Equally, with every system assessed every quarter
= Equal frequency wastes effort on low-risk systems and under-tests critical ones.
D)* By risk to the business
= Correct. Weigh criticality, data sensitivity, exposure and regulatory requirements, and focus effort where the risk is highest.
>> Design assessment strategies around risk, compliance obligations and change; validate that they cover what matters.

## D6-005 | 6.1 | 3
Q: A company's application runs partly in its own data center and partly on a SaaS platform. How should its assessment strategy cover the SaaS portion?
A)* Use the provider's attestations and test its own configuration
= Correct. In a hybrid environment you rely on independent attestations, such as SOC 2 Type II, for the provider's controls, and test what you control yourself: configuration and integrations.
B) Run an unannounced penetration test against the SaaS provider's infrastructure
= Testing a provider without permission may be illegal and breaches its terms.
C) Exclude it, because the SaaS provider is responsible for security
= Shared responsibility leaves the customer accountable for its data, identities and configuration.
D) Ask the provider to send its internal vulnerability scan results each week
= Providers rarely share raw internal results; independent attestations are the normal route.
>> For cloud and hybrid systems: rely on provider attestations for their side, and test your own configuration, identities and integrations.

## D6-008 | 6.2 | 1
Q: What is the main difference between a vulnerability assessment and a penetration test?
A)* Pen tests exploit weaknesses; assessments find them
= Correct. Exploitation shows real impact and attack paths; vulnerability assessments find and rank potential weaknesses.
B) Vulnerability assessments are performed by hand
= Most vulnerability assessments rely heavily on automated scanners.
C) Penetration tests need less authorization than scans
= Penetration tests need at least as much authorization, usually more, because they exploit systems.
D) A vulnerability assessment is more intrusive
= Penetration testing is the more intrusive of the two.
>> Vulnerability assessment: find and prioritize. Penetration test: exploit to demonstrate impact.

## D6-009 | 6.2 | 2

= Speed is not why they are more accurate.
B)* The scanner can check software and settings directly
= Correct. Logging in lets the scanner read configuration and versions instead of guessing from the outside, reducing false positives and negatives.

= All scans require authorization.
D) They focus on zero-day vulnerabilities
= Scanners look mostly for known vulnerabilities.
>> Credentialed scans see inside the host; uncredentialed scans show the attacker's external view. Both are useful.

C)* A false positive

= A true negative is correctly reporting that no vulnerability exists.

## D6-011 | 6.2 | 2
Q: During a penetration test, the testers are given network diagrams, source code and credentials in advance. What type of test is this?
A) Black box
= Black-box testers start with no knowledge, like an outside attacker.
B) Gray box
= Gray-box testers get partial knowledge, such as user credentials.
C) Blind test
= In a blind test, the testers know little about the target.
D)* White box
= Correct. White-box (crystal box) testers get full knowledge, allowing thorough coverage in less time.
>> Black box: no knowledge. Gray box: partial. White box: full knowledge.

## D6-012 | 6.2 | 2

= Correct. Purple teaming combines the red and blue teams collaboratively to improve detection and response.
C) Blue team exercise

## D6-016 | 6.2 | 2

## D6-018 | 6.2 | 3
Q: Testing executed every line of code, but not every true/false outcome of each decision. Which coverage measure is still incomplete?

= Functions were all called if every line ran.
B) Statement coverage
= Executing every line achieves full statement coverage.

= Correct. Branch coverage requires each decision to take both its true and false paths, which line coverage does not guarantee.
D) Loop coverage
= Loop coverage is a different measure, concerning loop iterations.
>> Coverage analysis: statement, branch, condition, function and loop coverage measure how thoroughly tests exercise code.

= Correct. A 30% bypass rate is a control failure to report; the remedy is a governed emergency process with review after the fact, not quiet acceptance.
D) Discipline the engineers who made the changes
= Blame does not fix the process that allowed or encouraged the bypass.
>> Report control failures even when outcomes were good; the fix is a governed process such as emergency change, not blame.

## D6-049 | 6.2 | 3
Q: A penetration test of a web application finds no high-risk issues. A week later, a researcher reports an authorization flaw that lets one customer see another customer's invoices. What MOST likely explains the miss?
A) Scanners, not human testers, should have been used for such flaws
= Scanners are weak at authorization logic; finding it needs tests designed around who should see what.
B)* The testers had only one customer login
= Correct. Cross-customer flaws only show up when testers hold accounts for two customers and request one's data with the other's session.
C) The researcher's probing introduced the flaw
= Testing finds flaws in the code; it does not create them.
D) A black-box test would have found the flaw
= A black-box test with no accounts would see even less; authorization flaws need authenticated tests across roles and tenants.
>> Authorization flaws need testers holding multiple roles and tenants; scope and credentials decide what a test can find.

## D6-050 | 6.3 | 3
Q: The board wants one measure showing whether the vulnerability management program is improving over time. Which metric serves this BEST?
A) The total number of vulnerabilities the scanners find each month
= Raw counts rise when scanning coverage improves, so they can mislead in either direction.
B)* The on-time fix rate for critical findings
= Correct. Remediation against an agreed deadline measures how well the program performs, whatever the number of findings.
C) The number of scans run each month
= Activity is not outcome; more scans do not mean less risk.
D) The number of security tools deployed
= Tool count says nothing about results.
>> Good security metrics measure outcomes against targets, such as fixes within the deadline, not raw activity or counts.
